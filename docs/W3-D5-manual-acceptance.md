## 3. 四角色循环检查

每个账号都由你直接在页面输入密码。成功后应先调用真实 `POST /api/auth/login`，随后 `GET /api/auth/me`；身份核验完成前不显示受保护内容。可在开发者工具中检查方法、路径、状态码及非敏感身份字段，避免复制或截图密码、Authorization 和 Token 响应。

| 账号 | 预期导航与检查 |
|---|---|
| demo_reporter01 | 身份与授权、我的报修、提交报修；不显示维修或管理入口 |
| demo_worker01 | 身份与授权、我的报修、提交报修、待处理任务、维修记录、本人维修档案；本人报修占位页说明 D-017 |
| demo_dispatcher | 按 AREA_SCOPE 显示工单管理、工单审核、智能派单、维修人员管理、管理看板；页面仅占位 |
| demo_sysadmin | 当前 seed 授予 BUSINESS_READ、INTERNAL_NOTE_READ、STATS_VIEW，因此显示身份与授权、工单管理、管理看板、系统概览；不显示审核、派单、人员管理 |

每个角色依次检查：

1. 成功登录后身份页的用户名、显示名和主要角色与 `/auth/me` 实际响应一致。
2. 导航链接可访问，业务页面明确显示占位说明，不呈现虚构业务数据。
3. 使用应用内链接导航；reporter/worker 手工输入 `/admin/review` 等受限 URL，应显示无权访问页面。sysadmin 手工输入未授权的 `/admin/dispatch`、`/admin/workers` 也应被拒绝。
4. 登录后通过应用内路由再次访问 `/login` 应回身份首页。直接在地址栏访问或按 F5 属于整页重载，会丢失内存 Token，重新显示登录页是当前预期行为。
5. 点击“重新查询身份”应产生真实 `/auth/me` 请求。
6. 点击“退出登录”应产生真实 `POST /api/auth/logout`，成功为 200 且 `data.revoked=true`；页面回到登录，受保护内容消失。
7. 退出后用浏览器返回按钮尝试查看旧页面，不能继续显示旧账号的受保护内容；然后在同一浏览器登录下一角色。

退出后旧 Token 的真实 401 此前已由独立后端 CTest 验证。本次反馈未单独确认浏览器“重放 XHR”，故不把该浏览器细项另记为已验证；如需复测，可在开发者工具支持时对退出前的 `/auth/me` 使用“重放 XHR”，期望401，无需复制或输出完整 Token。

## 4. 刷新、断网与敏感信息

1. 登录后按 F5：内存状态清除，受保护页面应转登录。localStorage/sessionStorage 不应出现本应用 Token。刷新并不等于服务端撤销；遗留会话到期后失效。
2. 在登录页时，终端 A 按 Ctrl+C 停止后端，尝试登录应显示后端不可用或超时，不应进入已登录状态。用终端 A 原命令恢复后可重试。
3. 已登录状态下若后端离线后退出，前端应清除本机状态，同时明确“服务端撤销尚未确认”，不能伪称退出请求成功。
4. 401 应清理失效状态，403 不应自动当作退出。现有前端单元测试已覆盖此差异，当前占位页不会主动调用尚未实现的业务 API。
5. 观察浏览器控制台是否有异常或凭证输出；不要开启请求体/请求头自动日志记录。页面、地址栏与错误通知不应出现 Token。

## 6. 保留的行为限制、未验证项目与风险

- Token 只存内存，整页刷新后需要重新登录；这是已确认的阶段行为，不提供刷新后持久登录。
- 前端清空 Token 不保证离线时服务端 Session 已撤销；服务端未撤销会话仍按其有效期处理。此前自动化测试覆盖离线退出提示，本轮未另行验证更多故障类型。
- 尚未完成完整登录限流，也未完成高并发或全面安全审计；内存凭证仍可能受 XSS 影响。
- 尚未进行跨机器首次部署验证。
- 完整工单业务 API 尚未开发。worker 导航符合 D-017，不等于已通过工单验收、返工或评价业务的浏览器端到端测试。
