# CampusFix 前端页面原型

> **版本**：V1.0（W1-D5 P0 冻结基线）
>
> **范围**：P0 页面、导航、交互与 API 映射；本文不包含 Vue 业务代码，也不表示页面已经实现。
>
> **技术输入**：Vue3 + Vue Router + Pinia + Axios + Element Plus + ECharts。
> **业务依据**：`docs/flows.md`、`docs/roles.md`、`docs/api-contract.md`。

## 1. 原型原则

- 页面只展示服务端返回的允许动作和字段；是否允许操作仍由后端按身份、资源范围、状态和 `version` 最终判断。
- 状态码使用 W1-D3 固定值，前端只做中文标签映射，不在请求中直接传目标状态或操作者。
- P0 每个账号只有一个主要角色。`worker` 菜单同时提供“本人报修”入口，但不会切换成 reporter 角色，也不会扩大维修任务范围。
- `sysadmin` 不自动获得业务菜单。菜单由 `/api/auth/me` 返回的明确 capability 与区域范围生成；接单、维修、验收、评价永远不能由管理员冒名操作。
- P0 保留后端 DRAFT 与显式 submit，但不做草稿箱、自动保存、恢复版本、复杂编辑历史等 UI。报修页内部先创建草稿以获得 `order_id`，完成可选图片上传后立即显式提交。
- 内部审核/调度备注只在授权管理页面渲染；普通详情 DTO 中根本不包含这些字段。
- 所有写按钮请求中禁用并显示 loading；409 时保留用户输入、刷新最新工单并明确提示“数据已变化”。

## 2. 页面导航树

```text
/login
└── /app                         AppLayout（已认证）
    ├── /report/new              本人报修（reporter、worker）
    ├── /my-orders               本人报修列表（reporter、worker）
    ├── /orders/:id              工单详情/公开时间线（按资源范围）
    ├── /worker/tasks            维修任务（worker）
    ├── /worker/profile          本人技能与负载（worker，只读）
    └── /admin                   管理布局（按 capability + 区域范围）
        ├── /admin/dashboard     调度看板与基础统计
        ├── /admin/orders        审核、待派、归档工单列表
        ├── /admin/dispatch/:id  候选推荐与确认派单
        └── /admin/workers       维修人员、技能、容量维护
```

`/system/users`、复杂权限配置、通知、排班、动态权重、导出和系统配置 UI 不属于 P0。sysadmin 若没有任何显式业务 capability，登录后进入只显示本人身份、当前授权摘要和“当前没有可用业务模块”的空入口；账号/权限数据由 P0 种子数据或受控初始化建立。

## 3. 四角色入口与菜单

| 主要角色 | 默认入口 | P0 菜单 | 明确禁止/隐藏 |
|---|---|---|---|
| `reporter` | `/my-orders` | 新建报修、我的工单、工单详情/验收/评价 | 审核、推荐、派单、人员管理、他人工单 |
| `worker` | `/worker/tasks` | 维修任务、本人技能与负载、本人报修、我的报修 | 他人任务、修改本人资质、审核、派单、验收/评价他人单 |
| `dispatcher` | `/admin/dashboard` | 管辖区看板、工单管理、调度、维修人员 | 冒名接单/维修/验收/评价、跨区域数据 |
| `sysadmin` | 首个获授权模块；无授权则空入口 | 仅 `/api/auth/me` 返回 capability 对应的管理菜单和范围 | 角色本身不显示全局业务菜单；永不显示接单/维修/验收/评价按钮 |

路由 `meta` 至少包含 `requiresAuth`、`allowedRoles`、`requiredCapability`。路由守卫只改善体验；即便用户手工输入 URL，后端仍必须拒绝越权 API。

## 5. 核心页面线框与交互

### 5.1 登录 `/login`

```text
┌──────────────────────────────┐
│          CampusFix           │
│ 用户名 [__________________]  │
│ 密  码 [__________________]  │
│                              │
│        [ 登 录 ]             │
│ 账号或密码错误 / 网络错误区  │
└──────────────────────────────┘
```

- 组件：`ElForm`、`ElInput`、`ElButton`、`ElAlert`。
- 校验：用户名和密码只做必填/长度检查；不在页面区分“账号不存在”和“密码错误”。
- 点击登录调用 API-01；成功后 AuthStore 保存 Token（具体安全持久化策略 W3 冻结），立即调用 API-03 获取角色/能力，再跳默认入口。
- 状态：提交中禁用；401 显示通用错误；网络失败提供重试；已登录访问 `/login` 跳回工作台。

### 5.2 新建报修 `/report/new`

```text
┌─ 新建报修 ─────────────────────────────────────────┐
│ 故障标题*      [_______________________________]    │
│ 故障分类*      [级联选择 ▼]   申报紧急度* [普通 ▼] │
│ 位置*          [校区/楼宇/楼层/房间 级联选择 ▼]    │
│ 期望上门时间   [日期时间，可选]                     │
│ 故障描述*      [_______________________________]    │
│                [_______________________________]    │
│ 联系人* [________] 联系电话* [________________]     │
│ 报修现场图（最多3张，每张≤5MiB）[上传][缩略图 ×]   │
│                                                      │
│                     [取消] [提交报修]                │
└──────────────────────────────────────────────────────┘
```

- 可见角色：reporter、worker。worker 始终以当前账号本人作为 `reporter_id`，页面无代报人选择器。
- 分类/位置分别调用 API-05/API-04；表单字段与 `work_orders`、API-06 完全同名。
- “提交报修”顺序：前端校验 → API-06 创建 DRAFT → 可选逐张 API-28 上传 REPORT 图片 → API-08 显式 submit → 跳 `/orders/:id`。
- 上传前校验扩展名、大小和数量只为体验；服务器会再次校验真实 MIME/权限/数量。缩略图删除调用 API-30。
- API-06 成功但上传/submit 失败时显示“报修尚未正式提交”，保留 `order_id/version` 并允许当前页面重试；不提供独立草稿箱或复杂恢复 UI。
- 重大安全故障在选择 URGENT 或相关分类时显示固定警示：“先联系学校应急值班渠道并确保现场安全，本系统不替代应急处置。”
- 不做“相似工单智能查重”或管理员代报（P1）。

### 5.3 我的工单 `/my-orders`

```text
┌─ 我的工单 ─────────────────────────────────────────┐
│ 状态 [全部 ▼] 分类 [全部 ▼]       [查询] [新建报修] │
├─────────────────────────────────────────────────────┤
│ 单号          标题       状态        更新时间  操作  │
│ WX...0001     插座无电   待审核      10:20    [详情]│
│ WX...0002     水管漏水   待补充      09:10    [详情]│
├─────────────────────────────────────────────────────┤
│                         < 1 2 3 >                    │
└─────────────────────────────────────────────────────┘
```

- reporter/worker 的“我的工单”调用 API-09 `view=reported`，只展示本人作为报修人的数据；worker 的维修任务另在 `/worker/tasks`。
- 组件：`ElSelect`、`ElTable`、`ElTag`、`ElPagination`、移动端 `OrderSummaryCard`。
- 空数据：插画/文本“暂无报修工单”并显示新建按钮；合法空分页自动回到上一页。
- 失败：内联 `ElResult` + 重试；401 由拦截器清理会话；403 不回退成全量数据。

### 5.4 工单详情 `/orders/:id`

```text
┌─ WX202610190001  宿舍插座无电 ── [待验收] ─────────┐
│ 基本信息：分类 / 位置 / 紧急度 / 描述 / 联系方式    │
│ 当前负责人：维修员A     版本：8                     │
│ 附件：[图1] [图2]       维修结果：已更换插座        │
├─ 进度时间线 ────────────────────────────────────────┤
│ ● 提交报修  09:05                                   │
│ ● 审核通过  09:20                                   │
│ ● 已派单    09:30                                   │
│ ● 提交维修结果 11:50                                │
├─────────────────────────────────────────────────────┤
│ [按权限与状态出现：补充并提交 / 取消 / 验收 / 评价] │
└─────────────────────────────────────────────────────┘
```

- 初始并发调用 API-10、API-11、API-26；附件预览使用 API-29，不拼接磁盘路径。
- reporter 操作：
  - `DRAFT/PENDING_SUPPLEMENT`：显示编辑表单和“提交”；API-07 + API-08。
  - 可取消前期状态：显示“取消”；API-12，DRAFT 原因可选，其余原因必填。
  - `PENDING_VERIFY`：显示“验收通过/未解决”；API-24。
  - `COMPLETED` 且无评价：显示“评价”；API-25。`CLOSED` 不显示评价入口。
- worker 作为维修负责人访问时显示任务所需详情，但不显示 reporter 验收/评价按钮；管理人员也不能看到冒名按钮。
- 时间线普通视图只渲染 `public_note`。管理视图仅当响应实际含 `internal_note` 时显示带锁图标的“内部信息”区。
- 404 使用统一“资源不存在或无权访问”；终态显示只读横幅，禁止编辑控件。

### 5.5 维修任务 `/worker/tasks`

```text
┌─ 我的维修任务 ─────────────────────────────────────┐
│ [待接单 2] [处理中 3] [待验收 1] [历史任务]         │
├─────────────────────────────────────────────────────┤
│ WX...001  插座故障  A栋301  紧急  [查看] [接单][拒单]│
│ WX...002  水管漏水  B栋204  普通  [到场][记进度][提交结果]│
└─────────────────────────────────────────────────────┘
```

- 数据调用 API-09 `view=assigned`，后端按当前/受控历史派单过滤；不允许客户端传 worker_id 获取他人任务。
- `PENDING_ACCEPT` 当前负责人：接单 API-19；拒单 API-20（原因必填）；申请转派 API-21。
- `IN_PROGRESS` 当前负责人：记录到场/维修进度 API-33；上传 REPAIR_RESULT 图片 API-28（独立最多 3 张、每张 ≤5 MiB）；提交维修结果 API-23；申请转派 API-21。到场按钮成功后禁用，进度备注可多次追加。
- `PENDING_VERIFY` 只读等待验收；返工后重新进入 IN_PROGRESS 并展示最新返工公开原因。
- 操作后用响应中的状态/version 更新缓存，并重新请求详情；409 显示“任务已被改派或状态已变化”。

### 5.6 本人技能与负载 `/worker/profile`

```text
┌─ 我的维修档案（只读） ─────────────────────────────┐
│ 人员编号 W0018   状态 在岗   服务区域 A校区          │
│ 当前任务 1 / 最大并行 3                              │
│ 技能：电工 Lv5 [有资质]；水暖 Lv2                    │
│ 档案变更请联系授权管理员                             │
└─────────────────────────────────────────────────────┘
```

- API-14 `mine=true` + API-15；worker 无编辑按钮。
- 数据为空/档案缺失显示明确错误并联系管理员，不创建临时档案。

### 5.7 管理工单 `/admin/orders`

```text
┌─ 工单管理 ─────────────────────────────────────────┐
│ 状态 [待审核 ▼] 分类 [全部] 区域 [授权范围] [查询]  │
├─────────────────────────────────────────────────────┤
│ 单号      标题     区域   状态    版本       操作    │
│ WX...001  插座无电 A栋   待审核   2   [详情][审核]  │
│ WX...002  漏水     B栋   待派单   3   [调度][取消]  │
│ WX...003  门锁     A栋   已完成   9   [关闭]         │
└─────────────────────────────────────────────────────┘
```

- API-09 `view=managed`；区域选项必须限制为 `/api/auth/me` 授权范围，后端仍重新过滤。
- 审核抽屉字段：最终分类、确认紧急度、通过/退回/拒绝、公开原因、内部备注；提交 API-13。退回/拒绝公开原因必填。
- PENDING_DISPATCH：“调度”跳 `/admin/dispatch/:id`；“取消”调用 API-12，原因必填。
- COMPLETED：“关闭”调用 API-27；未评价也允许关闭，但确认框明确提示“关闭后不能补充评价”。
- 转派待审批在工单详情管理区展示，批准/拒绝调用 API-22；两者审批原因均要求填写以便审计。没有待处理申请时不显示“改派”入口；管理员主动改派属于 P1。
- 未获得对应 capability 的按钮不渲染；直接 API 调用仍可能 403/404。

### 5.8 调度 `/admin/dispatch/:id`

```text
┌─ 智能调度 · WX...001 ──────────────────────────────┐
│ 工单：插座故障 / A栋301 / 已确认紧急度：高          │
│ [重新计算推荐]  计算版本 v3                          │
├─────────────────────────────────────────────────────┤
│ 选择  维修员  总分  技能 区域 负载 效率 评价 值班   │
│ (●)   A       80.3  100  100  67   60   60   0      │
│ ( )   B       75.0   80  100  75   60   60   0      │
│ 推荐理由 / 风险：历史样本不足                       │
├─────────────────────────────────────────────────────┤
│ 排除摘要：任务已满 2；技能不符 1；不在岗 1          │
│ 其他合格人员 [维修员D · 排名4 ▼]                    │
│ 非 Top 3 原因 [_______________________________]      │
│                                      [确认派单]      │
└─────────────────────────────────────────────────────┘
```

- API-17 返回 `top_candidates`、`other_eligible_candidates`、分项分、样本量、解释和排除汇总；页面不自行计算或更改分数，打开/刷新推荐不会产生业务写入。
- 空候选是成功空状态，不显示派单按钮，展示分组原因和“返回工单列表”。不得出现“忽略容量/资质继续派单”。
- 选择候选后 API-18；使用最新 `order_version` 作为 `expected_version`。若人工选择非 top 3 的合格人员，原因必填。
- 409 后关闭确认 loading，重新调用 API-10/API-17；若已派单则跳详情并提示另一请求已完成派单。

### 5.9 维修人员管理 `/admin/workers`

```text
┌─ 维修人员 ─────────────────────────────────────────┐
│ 区域 [授权范围] 状态 [全部] 技能 [全部] [查询]      │
├─────────────────────────────────────────────────────┤
│ 编号  姓名  区域  在岗状态  负载/容量  技能   操作  │
│ W018  A     A栋   在岗      1/3       电Lv5 [编辑]  │
└─────────────────────────────────────────────────────┘

编辑抽屉：
服务区域 [A栋▼]  在岗状态 [AVAILABLE▼]  最大并行 [3]
紧急值班 [否]    技能 [电工 Lv5 已认证] [+ 添加]
                                             [保存]
```

- 列表/负载 API-14/API-15；保存 API-16。
- max 必须为正整数；技能 level 1～5；降低容量低于当前任务数时服务端 422，页面保留输入并解释原因。
- dispatcher 只能编辑授权区域；sysadmin 只有 `WORKER_MANAGE` 明确授权时显示此页。
- P0 不显示排班日历、动态权重、跨区域例外或删除人员。

### 5.10 管理看板 `/admin/dashboard`

```text
┌─ 调度看板 ─────────────────────────────────────────┐
│ [待审核 4] [待派单 3] [处理中 5] [待验收 1]        │
├──────────────────────┬──────────────────────────────┤
│ 工单趋势（折线图）   │ 类别分布（柱状/饼图）        │
├──────────────────────┼──────────────────────────────┤
│ 人员负载对比         │ 统计日期 [起] - [止] [查询]  │
└──────────────────────┴──────────────────────────────┘
```

- 摘要 API-31；时间范围统计 API-32；指标卡点击跳 `/admin/orders?status=...`。
- ECharts 在容器尺寸变化时 resize；无数据展示空态而非伪造 0 趋势；接口失败只影响对应卡片并允许局部重试。
- 页头显示“统计范围：已授权区域”，sysadmin 也不能看到未授权全局数字。

## 6. 关键操作二次确认

| 操作 | 交互 | 必填内容 | 冲突处理 |
|---|---|---|---|
| 正式提交报修 | 确认摘要，提示提交后进入审核 | 无额外原因 | 409 刷新 version，保留表单 |
| 取消工单 | `ElDialog` 显示单号与不可恢复提示 | DRAFT 可选；已提交必填原因 | 409 关闭按钮 loading，刷新详情 |
| 审核拒绝/退回 | 审核抽屉内确认 | 公开原因必填；内部备注可选 | 409 保留原因并刷新状态 |
| 确认派单 | 显示人员、负载和版本 | 偏离 top 3 时原因必填 | 409 告知已被其他请求处理 |
| 拒单 | 确认后将释放本人任务 | 原因必填 | 409 刷新任务列表 |
| 申请/审批转派 | 显示当前负责人和状态 | 申请及审批原因必填 | 409 刷新申请/工单 |
| 提交维修结果 | 展示摘要与图片数量 | `repair_summary` 必填 | 409 保留输入，刷新详情 |
| 验收不通过 | 明示工单返回处理中 | 原因必填 | 409 刷新详情 |
| 验收通过 | 明示进入 COMPLETED | 无额外原因 | 409 刷新详情 |
| 关闭 | 明示终态且关闭后不可补评 | 备注可选 | 409 刷新；不重试旧版本 |
| 删除未提交附件 | 图片缩略图确认 | 无 | 状态变化后禁止并刷新附件 |

确认框不能把服务端 403/409 变成静默成功；成功 Toast 只在收到 2xx 且 `code=0` 后显示。

## 8. 通用页面状态

| 状态 | 统一表现 |
|---|---|
| 首次加载 | 主区域 skeleton；按钮禁用；避免空白闪烁 |
| 局部提交 | 当前按钮 loading，相关字段禁用；其他只读区保持可见 |
| 空数据 | `ElEmpty` + 与角色相关的下一步；不把空数组当错误 |
| 400/422 | 表单字段下方错误 + 顶部摘要；焦点移到第一个错误字段 |
| 401 | 只弹一次“登录已失效”，清 AuthStore，带安全 return URL 跳登录 |
| 403 | `ElResult status=403`；不展示资源内容，不自动换账号重试 |
| 404 | “资源不存在或无权访问”；不区分越权与真实不存在 |
| 409 | `ElAlert` 提示状态/版本已变化，保留未提交输入，提供“刷新最新数据” |
| 413/415 | 上传项旁显示大小/类型错误，其他合法文件不自动重传 |
| 500/503/网络失败 | 显示 `request_id`（如有）和重试按钮，不展示堆栈/SQL |
| 部分统计失败 | 单卡片错误与局部重试，不清空其他成功图表 |

Axios 拦截器只处理协议级行为；业务码由页面/组合式函数决定文案。写请求不得自动重放，否则可能造成用户误解；读取请求可有限重试。

## 11. W1-D5 冻结结论

1. 无业务授权的 sysadmin 只看到身份/授权摘要空入口，不新增 P0 用户管理后台。
2. 创建—上传—提交失败允许在当前页重试；不提供独立草稿箱。
3. 评价只展示单项总分和评论；关闭后不显示评价入口。
4. 到场/进度使用 API-33；附件按 REPORT/REPAIR_RESULT 分别显示剩余数量。
5. 初次派单可选择其他合格人员，非 Top 3 原因必填；无申请主动改派不提供按钮。
6. 本文仅为原型，页面和测试仍为待实现、待执行。
