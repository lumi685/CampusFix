## W1-D5 冻结决策（新增记录，不替代 D-001～D-010 的历史）

### D-011 P0 工单生命周期细则

- 日期：2026-10-21
- 状态：已接受
- 最终决定：创建先进入 `DRAFT`，首次显式提交时并发安全地生成工单编号；`COMPLETED` 可不评价直接关闭，评价不改变状态且 `CLOSED` 后拒绝新评价；`DRAFT` 取消原因可选，其他允许取消的已提交状态原因必填。
- 影响：状态机、API、数据库、UI 和验收测试统一采用此规则。

### D-012 身份、授权与字段可见性

- 日期：2026-10-21
- 状态：已接受
- 最终决定：每账户一个主要角色；`worker` 可作为本人报修；管理员代报和复杂角色切换为 P1。`sysadmin` 角色不天然取得业务权限，业务读取、审核、调度、取消、关闭、人员维护、统计和内部备注读取均须能力码与数据范围显式授权，且不能冒充维修员或报修人。
- 能力码：`BUSINESS_READ`、`REVIEW`、`DISPATCH`、`CANCEL`、`CLOSE`、`WORKER_MANAGE`、`STATS_VIEW`、`INTERNAL_NOTE_READ`。dispatcher 的区域使用 `AREA_SCOPE`；sysadmin 的每条动作能力通过自身 `scope_location_id` 限定范围，NULL 才表示该能力全局；`AREA_SCOPE` 本身不授予动作。
- 返回白名单：公共时间线只返回 `id/action/from_status/to_status/public_note/actor{id,display_name}/created_at` 及获准的附件摘要；授权管理人员可额外获得 `internal_note`，以及按动作允许的 `review_action/category_id/approved_urgency`、`assignment_id/worker_id/assign_reason/candidate_rank`、`transfer_request_id/decision`、`rework_count`。禁止直接返回 `metadata_json`、凭证、`stored_path` 或无关联系方式。

### D-013 调度推荐、评分与派单快照

- 日期：2026-10-21
- 状态：已接受
- 最终决定：推荐预览保持只读，不写调度快照；返回 Top 3 和其他合格人员。初次派单可选择任何仍满足硬约束的合格人员，选择非 Top 3 时理由必填；确认派单时重新计算硬约束与排名，并在同一事务保存最终候选依据、权重快照、选中人员、派单和日志。
- 历史效率：每个有效样本 `clamp(100 × 类别目标分钟 / 实际分钟, 0, 100)`，实际分钟为接单至该次最终维修结果提交，最小 1 分钟；取最近 20 个以 `COMPLETED` 正常结束的有效派单，少于 3 个样本时为 60，否则算术平均并四舍五入到 1 位小数。
- 历史评价：取最近 20 个由该维修员最终完成工单的有效单项评价，`平均星级 × 20`；少于 3 个样本时为 60，否则四舍五入到 1 位小数。

### D-014 P0 改派边界与过程事件

- 日期：2026-10-21
- 状态：已接受
- 最终决定：P0 改派仅支持维修员发起、管理员审批；管理员无申请主动改派为 P1。批准后结束原有效派单、释放负载并回到 `PENDING_DISPATCH`，再走普通派单。维修员可在 `IN_PROGRESS` 追加一次 `ARRIVED` 和多次 `PROGRESS_NOTE` 事件，不新增工单状态。
- 一致性：维修结果提交后仍为待处理的转派申请须在同一事务标记为 `SUPERSEDED`。

### D-015 验收、评价、附件与统计口径

- 日期：2026-10-21
- 状态：已接受
- 最终决定：验收通过时在同一事务将有效派单以 `COMPLETED` 结束并释放负载；评价模型为每单一次 `score` 1～5 加可选评论。报修现场图与维修完成图分别最多 3 张，逐文件校验类型、大小（不超过 5 MiB）和访问权限。完成率按统计区间内 `submitted_at` 的工单构成固定队列，分子为该队列当前状态为 `COMPLETED` 或 `CLOSED` 的工单数。

### D-016 数据与接口基线

- 日期：2026-10-21
- 状态：已接受
- 最终决定：P0 使用 16 张业务表与 33 个 REST API；接口编号以 `docs/api-contract.md` 的 API-01～API-33 为唯一基线，测试编号以 `docs/requirements-trace.md` 的登记为唯一语义来源，状态转换编号以 `docs/flows.md` 的 T-01～T-23 为唯一来源。
- 一致性：SQLite 派单容量竞争使用短 `BEGIN IMMEDIATE` 事务；历史数据原则上不物理删除；外键删除策略和事务边界以数据库设计及架构文档为准。
