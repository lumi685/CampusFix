## 2. 实现与安全规则

1. AiReportDraftPreview保留编辑/复制/重新生成/普通报修/取消，新增“使用此建议填写报修”。父页按真实前端认证身份、reporter/worker、建议结构、未过期、无请求及未处理错误控制；点击先告知不创建/提交。取消不传递；确认后再次核对会话revision、当前编辑内容和源页面仍有效。
2. reportDraftHandoff仅运行时内存。严格六字段白名单、独立字符串/数组副本；不存凭据/业务ID/完整聊天。绑定现有credential revision及身份，五分钟过期，主动计时清理且消费时重验；consume无论成功失败都清空，只能消费一次。不用URL/query/fragment、history state、localStorage/sessionStorage、后端存储或新Token体系。
3. credentials仅新增不传Token的变更订阅，不改认证/失效语义。退出开始、认证失效、凭据替换和pagehide清交接；同账号新登录revision不同，其他账号/角色拒绝。源页先复制后导航，卸载flow.clear不破坏副本；导航失败/异常/重定向后丢弃未消费ticket。目标页仅setup消费一次，退出/pagehide/卸载清提示与正式字段，迟到异步请求不重新预填。
4. ReportNewView仅将确认快照title/description一次性写入表单；空值/独立未知、null、待补充等占位文本保持空，不造默认内容。category_hint/location_hint/missing_information/safety_note单独作为文字提示显示，不入payload，不映射目录ID。所有展示使用文本插值/VNode，非HTML执行。
5. 真实分类与位置仍通过原CatalogPicker/API加载，不自动选首项，不猜ID、不硬编码seed编号、不增加“必须叶子/ROOM”限制。联系人、电话、日期不预填，紧急度仍NORMAL；URGENT原提醒和独立危险提醒保留。人工修改后无watch重新同步AI内容。
6. AI来源首次提交先原reportPayload验证，再展示用户当前实际字段（含真实目录ID、最终标题/描述、紧急度与联系方式），不是旧建议。确认取消不调用create；确认后仅调用原reportSubmission.send，创建DRAFT后同ID/version显式submit。已知草稿失败重试不再走第二次创建确认；409读取原单、未知创建结果不盲目重建。普通手工报修不增加AI确认。
7. 正式页对原create/submit/detail调用添加当前会话前置检查，不改reportSubmission实现；创建在途时退出/更换凭据，不用新会话继续submit。已经发出的旧请求可能已创建一张合法DRAFT，前端清理不承诺撤回已提交服务器的写入。

提示和确认仅为用户体验，不能保证模型事实正确、阻止恶意客户端修改或替代后端权限/字段/引用/状态/版本/事务检查。
