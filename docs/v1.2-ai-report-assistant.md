# CampusFix V1.2：AI 对话辅助报修（第一阶段）

日期：2026-10-24。需求编号 **FR-AI-01**；扩展接口 **AI-01**。这是用户批准的独立版本扩展，不修改 W1 P0、API-01～33、Schema 或 W6 调度设计。

## 1. 范围与身份

已登录 reporter、worker 均可为本人报修咨询；不切换主要角色。dispatcher/sysadmin 即使有管理授权也不得使用。AI 不代表原报修人执行任何业务动作。

第一阶段只有文字输入、真实模型回复、多轮上下文、忙碌/失败/重试、清空、安全提示及 `/report/new` 导航。没有自动填写/创建/提交工单、分类决策、图片、语音、RAG、工具调用、派单、云端历史或新数据表。W6 暂缓但设计原样保留。

## 2. 架构及数据边界

```text
ReportAssistantView → reportAssistant API → 既有 /api Axios / Vite
  → AuthGuard → AiReportAssistantController → AiRequestLimits
  → ModelProvider / ChatCompletionsProvider → WinHTTP → DeepSeek
```

- AuthGuard 复用现有数据库会话验证，读取 users/auth_sessions/management_grants 等身份信息。这是认证必需的既有只读行为，不承诺整条请求完全不碰数据库。
- AI 校验、限额及 Provider 不接收数据库连接/路径，不查询工单、人员、分类或授权表，无 Repository、SQL、业务工具或数据库写入。
- Controller 负责 HTTP/身份角色/统一响应，Service 负责输入及额度；Adapter 负责真实服务协议。已有认证、RBAC 和工单模块不重构。
- 使用已有 Trantor 4线程任务队列执行同步 WinHTTP，入队前并发准入，最多4个任务，不阻塞 Drogon 事件循环，不建立无界模型等待队列。
- Provider 接口可替换；当前具体实现使用 DeepSeek 的非流式 Chat Completions。用户明确批准 Windows WinHTTP 系统传输，仅链接 Winhttp.lib，不安装 SDK 或更改 vcpkg 基线。

## 3. 真实服务协议与配置

实际选定服务商为 **DeepSeek**。首次实现阶段仅做本地假模型测试；后续用户已在真实浏览器完成真实DeepSeek六场景验收，6/6确认通过，Codex未独立执行这些人工操作。用户未提供本次实际核对的模型名称与Base URL具体值，不猜测、不将配置示例当实测配置。协议核对来源：[首次调用](https://api-docs.deepseek.com/zh-cn/)、[Chat Completions](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)，核对日期2026-10-24。

服务端读取以下环境变量，读取一次，变更后需重启：

| 变量 | 示例/约束 |
|---|---|
| CAMPUSFIX_LLM_BASE_URL | 本人已核对的DeepSeek Base URL；不含 `/chat/completions`，可含版本前缀；尾部斜杠移除；本次实际值未提供 |
| CAMPUSFIX_LLM_API_KEY | 仅后端进程环境；不写入命令参数、文件、Vue 或聊天 |
| CAMPUSFIX_LLM_MODEL | 必填，使用本人已核对且账户可用的模型；不默选、猜测或自动升级；本次实际值未提供 |
| CAMPUSFIX_LLM_TIMEOUT_MS | 默认30000；整数100～45000，毫秒 |

### 认证数据库启动前提与登录500排查

AI-01经过既有AuthGuard，真实登录还必须配置 **CAMPUSFIX_DB_PATH**。在启动后端的同一PowerShell终端，将其指向已经迁移且含可登录账号的实际SQLite文件；确认文件存在，并在修改变量后重启后端，使进程继承新配置。不要仅设置LLM变量后就认为认证数据库已就绪，也不要为排查而批量启用账号或重置已有数据。

用户实际遇到的登录500已定位为缺失CAMPUSFIX_DB_PATH；正确设置数据库路径、重启后端后，用户确认登录和AI对话恢复正常。本轮仅按用户反馈记录，没有复现错误、重新执行HTTP或检查数据库内容；实际文件名未提供，不假填路径。健康检查仍独立于数据库，health成功不能证明登录配置正确。

Adapter 请求 `${BASE_URL}/chat/completions`，使用 Bearer Key、JSON，包含 `model/messages/stream=false/max_tokens=512/thinking:{type:"disabled"}`。可信 system 消息排首位，用户/助手历史原顺序附后。没有 tools、流式输出、思维链显示或自动重试。只读取 `choices[0].message.content`，要求 assistant、完整 stop；截断、工具回复或异常结构返回安全错误。

远程配置必须 HTTPS，系统证书链/主机名验证默认开启，未设置忽略证书错误。仅允许 `http://127.0.0.1:<port>` 用于独立测试替身/本地开发，不把它算成真实 DeepSeek。拒绝 URL 凭据、查询串、片段及控制字符。禁止重定向、自动 Windows 身份认证和 Cookie，不将 Key 转给其他目标。

使用 WinHTTP 分阶段有限超时，并在发送、接收及每次读取前检查剩余截止时间；慢响应持续读取也受期限约束。**WinHTTP DNS/连接/发送超时是分阶段的，不承诺精确的30秒总墙钟截止**。前端独立185秒超时覆盖配置的阶段上界，不自动重试。最大上游响应头16KiB，正文64KiB，固定8KiB读取缓冲；接收中超限即失败，不在完整无界接收后才检查。输出最多1500个 Unicode 标量，截断/超长不作为成功回复展示。

## 4. 上下文与隐私

- 消息只存在页面局部响应式状态。显示最多12条；发送最多12条、每条1500、合计9000个 Unicode 标量。超限时前端移除最早完整消息，保证首尾 user，保留当前消息；服务端不静默截断非法请求。
- 每次发送真实当前上下文，服务端独立注入 `report-assistant-v1` 提示词。客户端 assistant 标签不可信，不授予身份或更改提示词。
- 首次发送前勾选明确同意第三方数据告知。清空后同意状态也重置。
- 发送失败保留用户消息但不造助手回复；用户可以显式重试同一上下文，或修改后再发，不重复追加相同失败输入。
- 离开/卸载页面、pagehide、退出/认证失效、清空时中止浏览器等待、删除本地上下文，并通过代次编号丢弃迟到回复。不写 localStorage/sessionStorage、数据库或 URL。
- 中止/清空不能撤回已经发送给 DeepSeek 的数据、停止已发生的计费或保证服务商删除；服务商自身留存政策需用户另行了解。服务端在途请求结束前仍占额度。
- 不打印原始 Authorization、Token、Key、对话或上游正文；只记 HTTP 状态与 request_id。错误从固定白名单映射，不返回上游原文。若成功回复意外含实际配置 Key，拒绝返回。
- 既有内存 Token 策略不变，整页刷新后需重新登录。

## 5. 成本与并发

固定当前单进程额度（失败的上游尝试也计入）：

| 维度 | 限制 |
|---|---|
| 单服务端认证 Session | 同时1个；滚动60秒10次；滚动1小时60次 |
| 整个进程 | 同时4个；滚动1小时200次 |
| 限额记录 | 最多1024个 Session 摘要，按过期窗口清理；不存原始 Token |

输入/角色/配置失败不消耗上游额度；已接纳的超时/失败仍计数。同会话并发返回429 AI_REQUEST_IN_PROGRESS；进程满返回429 AI_BUSY；次数超限返回429 AI_RATE_LIMITED。没有自动排队或重放。进程重启会重置额度，多实例不共享计数；这不是生产级计费上限或完整反滥用系统。

## 6. 安全与人工验收边界

可信模板源文件 `backend/prompts/report-assistant-v1.txt`，CMake 生成私有头文件嵌入后端，保证提示词不依赖当前目录；修改模板需重新构建。不包含密钥，不发给前端。

保持用户批准的16条规则：安全低风险排查、少量澄清、不拆电箱/裸线/带电操作、不编造现场检查/联系方式/工单状态、忽略提示词注入、不索取密码等信息、无法解决引导正式报修。提示词及页面安全横幅都**不是危险识别或模型永不违规的证明**；真实语义行为需人工验证。模型输出纯文本，不用 v-html，不执行工具或链接指令。

### 后端密钥安全输入示例（由用户本机执行）

```powershell
# 以下占位值必须由本人核对后替换，不是此次人工验收的实际配置记录。
$env:CAMPUSFIX_DB_PATH = (Resolve-Path -LiteralPath '<已迁移且含可登录账号的实际SQLite文件>').Path
$env:CAMPUSFIX_LLM_BASE_URL = '<本人已核对的DeepSeek Base URL>'
$env:CAMPUSFIX_LLM_MODEL = '<本人已核对的可用模型名称>'
$env:CAMPUSFIX_LLM_TIMEOUT_MS = '30000'
$llmSecret = Read-Host 'DeepSeek API Key（不会回显）' -AsSecureString
$llmSecretPointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($llmSecret)
try { $env:CAMPUSFIX_LLM_API_KEY = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($llmSecretPointer) }
finally { [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($llmSecretPointer); $llmSecret.Dispose(); Remove-Variable llmSecret, llmSecretPointer }
# 以上变量必须在启动后端的同一终端设置；修改配置后先正常停止旧服务再重启。
.\scripts\start-backend.ps1
# 服务停止后：
Remove-Item Env:CAMPUSFIX_LLM_API_KEY -ErrorAction SilentlyContinue
```

进程环境不是秘密保险箱：同用户/高权限进程仍可能读取。不要把 Key 放入启动脚本、前端 VITE_*、命令行明文或聊天；不要执行输出所有环境变量的诊断。
